Teoria · Paralelismo

1.SIMD e MIMD

🎼 SIMD

Single Instruction, Multiple Data

  • Uma instrução aplicada a vários dados de uma vez
  • CPUs modernas (AVX, SSE), GPUs e NumPy
  • Ideal para vetores, imagens e matrizes
  • Ex.: somar 8 pixels ao mesmo tempo

🏭 MIMD

Multiple Instruction, Multiple Data

  • Várias instruções sobre vários dados
  • CPUs multi-core e clusters de GPUs
  • Cada núcleo faz uma tarefa diferente
  • Ex.: CPU processando áudio + vídeo ao mesmo tempo
🍎 Analogia: SIMD é um professor ditando a mesma instrução para a turma toda. MIMD são vários professores ensinando matérias diferentes a turmas diferentes, ao mesmo tempo.
Teoria · Taxonomia de Flynn

2.Classificando as arquiteturas

Flynn classifica as arquiteturas por quantas instruções e quantos dados fluem ao mesmo tempo.

ModeloInstruçõesDadosExemplo
SISD11CPU clássica sequencial
SIMD1MúltiplosGPU, extensões AVX/SSE, NumPy
MISDMúltiplas1Raro (pipelines especializados)
MIMDMúltiplasMúltiplosCPU multi-core, clusters
💡 No dia a dia da IA, os dois modelos que importam são o SIMD (a GPU aplicando a mesma conta em milhares de dados) e o MIMD (vários núcleos tocando tarefas diferentes).
Teoria · Conjunto de Instruções

3.RISC vs. CISC

📱 RISC

Reduced Instruction Set

  • Instruções simples e de tamanho fixo
  • Pipeline eficiente e previsível
  • Menor consumo de energia
  • Exemplos: ARM (Raspberry Pi, smartphones, Apple Silicon)
conceito 
ADD R1, R2, R3   # tamanho fixo: 32 bits

🖥️ CISC

Complex Instruction Set

  • Instruções complexas e de tamanho variável
  • Menos instruções para tarefas complexas
  • Maior consumo energético
  • Exemplos: x86/x64 (Intel, AMD) em desktops e servidores
conceito 
IMUL [mem], reg   # tamanho variável: 2 a 11 bytes
Provocação

4.Se RISC é mais eficiente, por que x86 domina?

RISC gasta menos energia por instrução, mas o CISC carrega décadas de software compatível (sistemas operacionais, jogos, aplicações). Trocar toda a base instalada tem um custo enorme — compatibilidade pesa tanto quanto desempenho.

🍏 Curiosidade: os chips Apple Silicon (M1/M2/M3) são RISC (ARM) e superam muitos x86 em performance por watt — provando que RISC compete em notebooks e desktops de alto desempenho.

Demonstração · SIMD na prática

5.Sequencial vs. vetorizado (NumPy)

O mesmo resultado, calculado de duas formas: um elemento por vez (SISD) e todos de uma vez (SIMD). O ganho é o que a GPU faz em escala gigante.

A ideia em 1 linha

conceito 
# 1 por vez          ->  c = [a[i] + b[i] for i in range(N)]
# todos de uma vez   ->  c = a_np + b_np   (SIMD)

O script mede os dois e mostra o speedup. Na CPU do laboratório (com AVX/SSE) o ganho já é grande; no Colab com GPU, o mesmo código testa também a placa.

O que o script faz

  • Detecta o backend: CuPy (Colab), DirectML (AMD/Windows) ou NumPy.
  • Mede sequencial vs. vetorizado e imprime o speedup.
  • Confere que os resultados são idênticos ao fim.
📄 Rode scripts/benchmark_simd.py (comentado linha a linha).
Atividade Guiada · Emulação

6.RISC vs. CISC na linha de comando

Dá para ver a diferença de arquitetura inspecionando a máquina. No Colab/Linux (x86) e num Raspberry Pi (ARM), os comandos revelam o tipo e o formato das instruções.

Comandos (Colab/Linux)

conceito 
# x86 (CISC): "Intel(R) Core(TM) i7..."
# ARM (RISC): "ARMv7 Processor rev 3 (v7l)"
cat /proc/cpuinfo | grep "model name" | head -1

# RISC = tamanho fixo  |  CISC = variável
objdump -d /bin/ls | head -30

No Windows/AMD, o script arquitetura_instrucoes.py detecta o tipo e lista os recursos SIMD da CPU (AVX2, SSE4…).

QEMU (emulação ARM)

  • O QEMU executa um binário de outra arquitetura (ex.: ARM) num PC x86.
  • Roda no Colab/Linux, inclusive via Docker.
  • Serve para comparar o formato das instruções entre as arquiteturas.
📄 Exercício de fixação e comandos completos em atividade.md.
Estudo de Caso · GPU

7.Como a GPU combina SIMD e MIMD

Processar uma imagem ilustra os dois modelos ao mesmo tempo: dentro de um warp é SIMD; entre blocos/SMs é MIMD.

Estrutura CUDA

Grid (toda a imagem) ├─ Block 0,0 → SM0 [MIMD entre blocos] ├─ Block 0,1 → SM1 └─ Block 1,0 → SM2 └─ Warp (32 threads) → SIMD Thread 0..31 → mesma instrução, dados diferentes

O que o script mostra

  • Converter uma imagem 1080p para tons de cinza.
  • Loop por pixel (CPU) vs. vetorizado (SIMD).
  • O ganho mostra por que a GPU é ideal para visão computacional.
📄 Rode scripts/estudo_imagem.py (comentado linha a linha).

Síntese e Tarefa de Casa

O que levar desta aula

  • SIMD — 1 instrução → múltiplos dados (GPU, NumPy, AVX)
  • MIMD — múltiplas instruções → múltiplos dados (multi-core, clusters)
  • RISC (ARM) — instruções simples e fixas → baixo consumo → embarcados/mobile
  • CISC (x86) — instruções complexas e variáveis → desktops/servidores
  • GPU — SIMD dentro do warp + MIMD entre blocos
