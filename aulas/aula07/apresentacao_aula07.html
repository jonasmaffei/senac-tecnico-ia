Teoria · Modelo de programação

2.Host e Device

🖥️ Host (CPU)

  • Código C/Python que roda na CPU
  • Aloca memória na VRAM
  • Transfere dados CPU ↔ GPU
  • Lança kernels na GPU
  • Coleta os resultados

🎮 Device (GPU)

  • Kernel: função que roda na GPU
  • Executado por N threads em paralelo
  • Cada thread tem um ID único (threadIdx)
  • Threads agrupadas em blocos
  • Blocos agrupados em grade
Teoria · Fluxo

3.O fluxo típico de um programa CUDA

1
CPU aloca arrays na VRAM — cuda.to_device()
2
CPU lança o kernel — kernel[blocos, threads](...)
3
GPU executa N threads em paralelo
4
CPU aguarda — cuda.synchronize()
5
CPU copia o resultado de volta — copy_to_host()
💡 O kernel é assíncrono: o host lança e segue. Sem synchronize(), você pode copiar um resultado incompleto.

4.threadIdx, blockIdx, blockDim, gridDim

IdentificadorSignificaExemplo
threadIdxÍndice local da thread no bloco.x = 0..255
blockIdxÍndice do bloco na grade.x = 0..N_blocos
blockDimNº de threads por bloco.x = 256
gridDimNº de blocos na grade.x = 3907
fórmula do índice global (1D) 
idx = blockIdx.x * blockDim.x + threadIdx.x
# atalho: idx = cuda.grid(1)
🧭 Em 2D (imagens): col, row = cuda.grid(2) — x é coluna, y é linha.

5.Numba: CUDA em Python

conceito 
@cuda.jit
def soma(a, b, c):
    idx = cuda.grid(1)
    if idx < c.shape[0]:
        c[idx] = a[idx] + b[idx]

O @cuda.jit compila a função para rodar na GPU. Cada thread calcula uma posição do vetor.

Saída esperada

Atividade · O problema da startup

6.FFT: CPU vs. GPU

conceito 
# CPU
np.fft.fft(sinal)

# GPU (mesma API!)
cp.fft.fft(cp.asarray(sinal))

A FFT é a operação central do pré-processamento de áudio. O CuPy entrega a mesma API do NumPy, mas executando na VRAM.

Speedup (T4, 4M pontos)

VersãoTempo
CPU (NumPy)~1200 ms
GPU (CuPy)~18 ms
Speedup~66×
