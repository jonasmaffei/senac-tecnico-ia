Teoria · Hierarquia de Memória

1.Os níveis de memória da GPU

Cada nível troca velocidade por tamanho: quanto mais perto do processador, mais rápida e menor.

⚡ Registradores

~1 ciclo · ~256 KB por SM · escopo thread. A memória mais rápida; uso automático pelo compilador.

🤝 Shared (SRAM)

~1–5 ciclos · ~48–164 KB por bloco · escopo bloco. O programador controla: é a chave da otimização.

📦 Cache L1 / L2

~20–50 ciclos · L1 ~128 KB, L2 ~6 MB · automático. Reduz os acessos à memória global.

🐢 VRAM Global

~400–800 ciclos · 8–80 GB · toda a GPU. Grande, mas lenta; exige acesso coalescente.

🖥️ RAM do host: a maior de todas (16–512 GB), mas acessada pela CPU. A cópia para a GPU passa pelo PCIe — o gargalo crítico.
Teoria · Pirâmide de Latência

2.Velocidade vs. tamanho

A largura da barra representa a velocidade: menor e mais rápido em cima; maior e mais lento embaixo.

Registradores
~1 ciclo
Shared (SRAM)
~1–5 ciclos
Cache L1 / L2
~20–50 ciclos
VRAM Global
~400–800 ciclos
RAM do sistema
milhares de ciclos
🎯 Regra 90/10: ~90% do tempo de processamento em IA é gasto esperando memória, não calculando. Otimizar memória vale mais que otimizar contas.
Teoria · RAM vs. VRAM

3.Diferenças fundamentais

CaracterísticaRAM (DDR5)VRAM (HBM / GDDR6)
Largura de banda~80 GB/s~3.35 TB/s (HBM3)
Latência típica~60–80 ns~100–200 ns (compensada pelo throughput)
Capacidade típica16–512 GB4–80 GB
TecnologiaDDR4 / DDR5GDDR6X / HBM2e / HBM3
ControladorCPUGPU
Transferência CPU↔GPUvia PCIe (~32 GB/s) — muito mais lento
💡 A VRAM é ~40× mais rápida que a RAM em largura de banda. O segredo da GPU é mover dados em massa, não acessá-los um a um.
Teoria · O Gargalo

4.O barramento PCIe

O PCIe 4.0 x16 oferece ~32 GB/s bidirecionais. Isso é ~100× mais lento que a largura de banda interna da VRAM.

🚧 Por isso, copiar dados da RAM para a GPU pode custar mais caro que o próprio cálculo. A otimização nº 1 é minimizar o tráfego PCIe.
# Caminho de um dado até a GPU RAM (host) │ ← cópia via PCIe (~32 GB/s) ← GARGALO ▼ VRAM (global) │ ← cache L1/L2 (automático) ▼ Shared (SRAM) ← controlada pelo programador ▼ Registradores ~1 ciclo
  • Mantenha os batches na VRAM e só traga o resultado no fim.
  • Use memória fixada (*pinned*) para acelerar cópias.
  • Evite idas e voltas CPU↔GPU a cada passo do treino.
Demonstração · Medir antes de otimizar

5.Monitorar a memória da GPU

No terminal (Linux/Colab)

conceito 
watch -n 1 nvidia-smi        # painel ao vivo
nvidia-smi --query-gpu=memory.used,memory.total \
           --format=csv

nvtop é a versão interativa com gráficos — ótima para ver a utilização caindo quando a GPU espera dados.

Via Python (pynvml)

conceito 
info = pynvml.nvmlDeviceGetMemoryInfo(h)
print(info.used / 1024**3, "GB usados")
📄 Veja scripts/monitor_memoria.py (comentado linha a linha).
Atividade Prática · Benchmark

6.RAM vs. VRAM na prática

A mesma soma de vetores, medida na RAM (CPU) e na VRAM (GPU) — mais o custo da cópia PCIe.

A ideia

conceito 
c_cpu = a_cpu + b_cpu        # RAM, CPU
c_gpu = a_gpu + b_gpu        # VRAM, GPU
a_gpu = a_cpu.cuda()         # cópia via PCIe (medir!)

Sem torch.cuda.synchronize() você mediria só o lançamento do kernel, não a execução.

O que o script faz

  • Mede a soma na RAM e na VRAM e o speedup.
  • Mede a transferência RAM→VRAM (o gargalo).
  • Sem GPU, mostra a hierarquia pela própria RAM da CPU.
📄 Rode scripts/benchmark_ram_vram.py e scripts/hierarquia_memoria.py.
Exercício Extra · CUDA

7.Memória global vs. compartilhada

🐢 Global (VRAM)

Cada thread lê direto da VRAM (~500 ciclos). Simples, porém lento quando o mesmo dado é lido várias vezes.

conceito 
c[idx] = a[idx] + b[idx]   # lê da VRAM

⚡ Compartilhada (SRAM)

Carrega uma vez para a SRAM do bloco (~5 ciclos) e reutiliza. É a base do tiling (Aula 8).

conceito 
sh[tid] = a[idx]           # global -> SRAM
cuda.syncthreads()         # sincroniza
📄 Requer GPU NVIDIA (Numba/CUDA). Comentado linha a linha no notebook aula03_memoria_gpu.ipynb.
