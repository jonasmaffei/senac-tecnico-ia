Teoria · O gargalo

1.A regra 90/10

⚡ Registradores

~1 ciclo · privado por thread · automático

🤝 Shared (SRAM)

~5 ciclos · por bloco · cache manual (tiling)

📦 Cache L1/L2

~30 ciclos · 32 KB / 6 MB · automático

🐢 Global (VRAM)

~500 ciclos · 8–80 GB · todos os threads

🎯 90% do tempo de execução de kernels de IA é gasto em acessos de memória. Otimizar memória vale mais que otimizar cálculo.
Teoria · Coalescing

2.Acessos eficientes à VRAM

✅ Coalescido

Threads consecutivas acessam endereços consecutivos.

Thread 0 -> dados[0] Thread 1 -> dados[1] Thread 2 -> dados[2] = 1 transação de 128B

❌ Não-coalescido

Threads acessam endereços espalhados (stride grande).

Thread 0 -> dados[0] Thread 1 -> dados[32] Thread 2 -> dados[64] = até 32 transações separadas
📄 Rode scripts/coalescing.py para ver a diferença de tempo.

tile_A[ty, tx] = A[row, kr]

for k in range(TILE):
    soma += tile_A[ty,k]*tile_B[k,tx]

🔁 Cada elemento é lido ~TILE vezes menos da VRAM.

4.Multiplicação de matrizes

Versão ingênua

conceito 
for k in range(K):
    soma += A[row,k] * B[k,col]
# cada iteração lê da VRAM

5.Medindo antes de otimizar

conceito 
inicio = cuda.event()
fim = cuda.event()
inicio.record()
kernel[...](...)
fim.record(); fim.synchronize()
t = cuda.event_elapsed_time(inicio, fim)

cuda.event cronometra na própria GPU — mais preciso que o relógio da CPU.

Síntese e Tarefa de Casa

O que levar desta aula

  • Registradores — ~1 ciclo, automáticos por thread
  • Shared memory — cache manual por bloco (~5 ciclos)
  • Memória global — ~500 ciclos; minimize com tiling
  • syncthreads() — barreira após carregar a shared
  • Coalescing — acessos contíguos = 1 transação de 128B
  • Nsight — encontra gargalos de memória e ocupância
