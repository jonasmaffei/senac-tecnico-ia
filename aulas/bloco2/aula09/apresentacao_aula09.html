Contexto · O problema

1.O lock-in do CUDA

CUDA é exclusivo de GPUs NVIDIA. Um pipeline escrito nas Aulas 7 e 8 simplesmente não roda numa GPU AMD ou Intel.

🔓 OpenCL (Open Computing Language), do Khronos Group, é o padrão aberto para programação paralela em qualquer dispositivo: GPUs, CPUs, FPGAs e DSPs.

Suporte por fabricante

FabricanteOpenCL
NVIDIA3.0 (CUDA é preferido)
AMD3.0 (via ROCm)
Intel3.0 (CPU + iGPU + Arc)
Apple1.2 deprecated (usa Metal)
Qualcomm2.0 (Snapdragon)
Teoria · Arquitetura OpenCL

2.Platform → Device → Context → Queue

Platform — conjunto de drivers do fabricante (NVIDIA, AMD, Intel). CUDA: não existe.
Device — CPU, GPU ou acelerador dentro da plataforma. CUDA: a GPU escolhida.
Context — agrupa dispositivos, memória e filas. CUDA: implícito.
Command Queue — envia kernels e cópias. CUDA: stream.
Kernel (OpenCL C) — compilado em tempo de execução (JIT). CUDA: @cuda.jit.
Buffer — região de memória no dispositivo (cl.Buffer). CUDA: device array.
🧭 A inicialização é explícita: descobrir a plataforma, escolher o dispositivo, criar o contexto e a fila — antes de qualquer kernel.

Demo · Primeiro kernel

4.Kernel OpenCL com PyOpenCL

OpenCL C 
__kernel void soma(
  __global const float* a,
  __global const float* b,
  __global       float* c) {
    int i = get_global_id(0);
    c[i] = a[i] + b[i];
}

Escrito em OpenCL C (string) e compilado em tempo de execução (JIT) para o dispositivo alvo — por isso é portável.

Fluxo

  • cl.Context + cl.CommandQueue
  • cl.Program(ctx, src).build() — compila JIT
  • cl.Buffer — aloca a/b/c no device
  • kernel(fila, (global,), (local,), ...)
  • fila.finish() + enqueue_copy
📄 Rode scripts/primeiro_kernel.py (comentado linha a linha).
⚠️ O global_size precisa ser múltiplo do local_size — por isso o kernel leva um if (i < n).

Teoria · Trade-offs

6.OpenCL: vale a pena?

✓ Vantagens

  • Roda em qualquer GPU (NVIDIA, AMD, Intel)
  • Fallback automático para CPU
  • Padrão aberto — sem vendor lock-in
  • Suporta FPGAs e DSPs

✗ Desvantagens

  • Mais verboso que CUDA (~3× mais código)
  • Ecossistema de IA menor
  • Compilação JIT: latência no início
  • PyTorch/TensorFlow preferem CUDA/ROCm
📌 Use OpenCL quando a portabilidade for mais importante que o desempenho máximo — ex.: software que precisa rodar no hardware do cliente.
