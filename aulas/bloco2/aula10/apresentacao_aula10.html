Teoria · Ecossistema

1.A stack do ROCm

Aplicação (PyTorch, TensorFlow, JAX)
Framework GPU (MIOpen, rocBLAS, rocFFT)
HIP Runtime — API de portabilidade CUDA/AMD
ROCr — ROCm Runtime (HSA)
KFD — Kernel Fusion Driver (módulo do Linux)
Hardware: GPU AMD (GFX9 / RDNA2 / CDNA3)
🔓 Diferente do CUDA (proprietário), todo o stack ROCm é open-source no GitHub.
Teoria · Equivalências

2.CUDA vs. ROCm/HIP

ComponenteCUDA (NVIDIA)ROCm (AMD)
Linguagem de kernelCUDA C/C++HIP C/C++
Compiladornvcchipcc
Álgebra linearcuBLASrocBLAS
Deep learningcuDNNMIOpen
FFTcuFFTrocFFT
Monitoramentonvidia-smirocm-smi
Containernvidia/cudarocm/pytorch
💡 hipify-clang converte kernels CUDA C/C++ para HIP automaticamente. Em PyTorch, muitas vezes não é preciso converter nada.
Teoria · Portabilidade

3."Zero código": o que muda?

O ROCm emula a API CUDA do PyTorch. O código Python é idêntico:

conceito 
device = "cuda" if torch.cuda.is_available() else "cpu"
modelo.to(device)

torch.cuda.is_available()  # True no ROCm também!

O que realmente muda

  • Ambiente: driver ROCm + hipcc
  • Monitoramento: rocm-smi no lugar de nvidia-smi
  • Imagem Docker: rocm/pytorch
  • Hardware: GPU AMD (MI300X, RDNA3…)
📄 Rode scripts/diagnostico_portabilidade.py.
Demo · Docker

4.A imagem rocm/pytorch

terminal 
docker pull rocm/pytorch:rocm6.2_...

docker run -it \
  --device=/dev/kfd \
  --device=/dev/dri \
  --group-add=video --group-add=render \
  --ipc=host --shm-size 8G \
  rocm/pytorch:... bash

Os dispositivos /dev/kfd e /dev/dri dão acesso às GPUs AMD.

Dentro do container

$ python3 -c "import torch; print(torch.cuda.is_available())" True # ROCm emula a API CUDA! $ python3 -c "import torch; print(torch.version.hip)" 6.2.0
