Teoria

1.Por que a GPU ganha? SIMD × SIMT

🧠 CPU — SIMD/MIMD

Poucos núcleos potentes, com execução sequencial e vetorial curta (AVX). Ótima para lógica complexa e baixa latência.

⚡ GPU — SIMT

Milhares de threads organizadas em warps (32), executando a mesma instrução sobre uma grade. Incomparável em dados massivos.

💡 Para c[i] = a[i] + b[i] com N = 10 milhões: a CPU faz em série; a GPU distribui por dezenas de milhares de threads ao mesmo tempo.
Prática

2.As 4 versões, do mais lento ao mais rápido

CPU

  • Python puro: laço interpretado — baseline lento.
  • NumPy: vetorizado, usa BLAS — já muito mais rápido.

GPU

  • Numba CUDA: escrevemos o kernel; controle total das threads.
  • CuPy: mesma API do NumPy, rodando na VRAM — sem reescrever.

Análise

3.Speedup: a GPU nem sempre ganha

Para vetores pequenos, a GPU perde: o custo de lançar o kernel (launch overhead) e de transferir via PCIe domina o trabalho útil.

A partir de um limiar de N, a GPU dispara — o paralelismo esconde os custos fixos.

Curva típica (speedup × N)

NSpeedup GPU
10 mil< 1× (perde)
100 mil~1×
10 milhõesmuito maior

Atividade extra

4.Norma: np.linalg.norm × cp.linalg.norm

O fecho do bloco: a norma de um vetor (raiz da soma dos quadrados) é uma redução — o tipo de operação em que a GPU brilha.

Medimos com vetores de 10 milhões de elementos.

N = 10.000.000 np.linalg.norm (CPU) : 12.40 ms cp.linalg.norm (GPU) : 1.05 ms Speedup : 11.8x
