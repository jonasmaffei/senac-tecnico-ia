Concorrência e Energia na GPU

Duas habilidades para operar uma GPU de verdade: dividi-la com justiça entre vários jobs e gastar menos energia sem perder desempenho.

Parte 1 · O caos

1.Quatro jobs, uma GPU: o que dá errado

Quando dois treinos usam a GPU ao mesmo tempo, cada um pega a memória que precisa sem pedir licença. A placa tem um limite — e ele estoura.

O resultado mais comum não é um erro bonito, é um travamento silencioso: o treino morre de madrugada e ninguém percebe.

Exemplo real (GPU de 8 GB)

[08:00:00] Job-A ocupa 5 GB [08:00:01] Job-B ocupa 5 GB (total: 10 GB > 8 GB) [08:00:01] Job-A: CUDA out of memory [08:00:01] Job-B: travou sem avisar
💡 A GPU é um recurso exclusivo, como uma impressora: melhor usar um job por vez.
Parte 1 · Um de cada vez

2.O lock: a "chave" da GPU

Pense numa sala com uma chave só. Quem pega a chave usa a sala; os outros esperam. Com a GPU é igual: o lock é a chave.

O jeito mais simples de criar essa chave é criar uma pasta. Criar pasta é uma operação atômica: se dois tentam juntos, só um consegue.

# 1o job: consegue criar a pasta -> usa a GPU os.mkdir("gpu.lock") # 2o job: a pasta ja existe -> espera

Em Linux, existe um comando pronto

$ flock -x gpu.lock -c "python treinar.py" # -x exclusivo; os outros esperam $ flock -n gpu.lock -c "..." # -n: tenta e desiste

Parte 1 · Justiça

3.A fila: quem entra, quando entra

Só o lock não basta: quem chegou por último pode entrar primeiro, e um job urgente pode esperar muito. A solução é uma fila com senha — como no banco.

Cada job cria um "ticket" com prioridade + hora + nome. O menor número entra primeiro; empate é resolvido pela hora (quem chegou antes).

1_hora_Job-Alta # prioridade 1 -> primeiro 2_hora_Job-Media # prioridade 2 3_hora_Job-Baixa # prioridade 3 -> por ultimo

Um cuidado importante

Se a fila só olha a prioridade, os jobs de baixa prioridade podem nunca rodar (uns chamam isso de starvation).

⏳ Para evitar: jobs que esperam muito ganham prioridade com o tempo (a técnica se chama aging).
Prática 1 · 4 jobs, 1 GPU

4.Vendo a fila funcionar

Vamos lançar 4 jobs de uma vez (dois urgentes, um médio, um de baixa prioridade) e observar o log. O lock garante um de cada vez; a fila decide a ordem.

  • Os dois de prioridade 1 rodam primeiro.
  • Depois o médio; por último o de baixa.
  • Nenhum dá erro de memória.

O log que você vai ver

Job-Alta-A -> executando Job-Alta-D -> executando Job-Media-C -> executando Job-Baixa-B -> executando Todos concluidos, sem OOM!
Parte 2 · Energia

5.Calor e o desperdício invisível

Toda GPU tem um teto de potência — os watts que ela pode consumir. Ex.: uma RTX 4090 = 450 W; uma Tesla T4 = 70 W.

Quando a placa esquenta demais (acima de ~83 °C), ela mesma reduz a velocidade para se proteger. Você perde desempenho e ainda gasta energia — o pior dos dois mundos.

💰 O caso da empresa

A GPU ficava no máximo de potência mesmo sem trabalho pesado. Foi a causa da conta 40% maior que o previsto — energia paga sem ganho.

🌡️ Em GPUs reais, o valor de potência é lido do sensor (via nvidia-smi / NVML) — é medido, não estimado.
Parte 2 · O controle

6.Power Limit: o ajuste que economiza

O Power Limit é um teto que você define, menor que o máximo. Na prática, cortar 20–30% da potência costuma custar só 5–10% de velocidade — troca muito boa.

$ sudo nvidia-smi -pl 200 Power limit for GPU 0 set to 200.00 W # via Python (NVML): pynvml.nvmlDeviceSetPowerManagementLimit(h, 200*1000)

Configurar exige sudo (Linux) — no Colab não é possível, por isso usamos um modelo para estudar o efeito.

Eficiência: resultado ÷ energia

Prática 2 · Economia

7.Achar o melhor ponto de consumo

Testamos vários Power Limits, medimos velocidade e consumo e calculamos a eficiência. O melhor ponto quase nunca é a potência máxima.

É uma decisão com dados: mais trabalho por menos energia.

Juntando as partes

8.Por que as duas coisas andam juntas

🔒 Ordem

Lock + fila garantem um job por vez, na sequência certa — sem erro de memória.

🌱 Economia

Limitar a potência reduz a conta de luz quase sem perder velocidade.

🧩 Medir certo

Com dois jobs ao mesmo tempo, a medição de energia fica errada — por isso o lock vem primeiro.

Síntese

O que fica desta aula

🔒 Um de cada vez

A GPU é recurso exclusivo: um lock evita travamentos e erros de memória.

📋 Na ordem certa

A fila com prioridade garante que o job urgente passe primeiro — sem esquecer os demais.

💰 Sem desperdício

Limitar a potência corta a conta de luz mantendo quase todo o desempenho.
