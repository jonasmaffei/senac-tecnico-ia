Teoria · Integração

1.Monitor integrado ao pipeline

O monitor evolui para rodar junto do treino: coleta de todas as GPUs e auto-encerramento quando o processo filho termina.

📡 Coleta automática

nvidia-smi a cada N segundos — temperatura, VRAM, potência e utilização de todas as GPUs.

📄 CSV estruturado

Log indexado por timestamp, pronto para análise com pandas e geração de dashboard.

🛑 Auto-encerramento

Monitora o PID do treinamento (kill -0) e para sozinho quando o processo encerra.

📄 O script completo está em scripts/monitor_treinamento.sh, comentado linha a linha.
Prática · Python

2.Integrar o monitor ao train.py

Em vez de rodar o monitor em outro terminal, o próprio Python o inicia em background com subprocess.Popen.

Ciclo de vida compartilhado

  • Iniciar: Popen antes do loop de treino
  • Encerrar: no bloco finally:
  • Garantia: o monitor morre com o treino, mesmo com erro ou Ctrl+C

💡 Por que importa

Sem o finally, um monitor órfão continua consumindo CPU e poluindo logs. O ciclo de vida compartilhado garante limpeza automática.

Prática · Alertas

3.Alertas multi-canal

Com variáveis de ambiente configuradas, o script dispara alertas em vários canais simultaneamente — log local é sempre ativo.

⚠️ Thresholds graduais: WARN a 82 °C / 85% VRAM e CRITICAL a 90 °C / 95% — dá tempo de reagir antes do OOM.
Prática · Visualização

4.Dashboard com pandas + matplotlib

Com o CSV coletado, gere o relatório visual das 4 métricas principais ao fim de cada sessão.

🌡️ Temperatura

Curva em °C com linhas de WARN/CRITIC — revela throttling.

⚡ Utilização

% de uso da GPU — queda no meio do treino indica gargalo no DataLoader.

💾 VRAM & Potência

Memória usada (GB) e consumo (W) — detecta vazamentos e OOM iminente.

Produção · systemd

5.Monitor como serviço do sistema

Para monitorar GPUs mesmo sem treino ativo, registre o monitor como serviço systemd — reinicia sozinho em caso de falha.

Boas práticas

  • Nunca rode como root — usuário dedicado, leitura apenas
  • Rotacione logs com logrotate (evita disco cheio)
  • Restart=on-failure + RestartSec=10s

🔄 Alternativa: cron

Sem systemd, use @reboot no crontab para iniciar o monitor com o servidor. Menos robusto, porém mais simples.
